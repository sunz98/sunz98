# 백엔드 개발자 포트폴리오 기획안

상태: 1단계 검토안. 디자인·구현·배포는 다음 단계에서 진행한다.

## 목적과 방문 흐름

국내 IT 기업의 신입 백엔드 채용을 위한 한국어 중심 포트폴리오다. 메인에서 지원 분야와 대표 경험을 파악하고, 프로젝트 상세에서 기술적 판단의 근거를 확인한 뒤 GitHub·PDF 이력서·연락처로 이동하도록 구성한다.

- 첫 화면: 이름, 지원 분야, 근거가 있는 소개 한 문장, 프로젝트 보기, 이력서.
- 메인 훑어보기: 기술 사용 맥락, 대표 프로젝트, 개인 기여, 교육·경험.
- 상세 읽기: 문제 → 제약 → 선택과 대안 → 구현 → 검증 → 한계와 회고.

## 정보 구조

| 화면/영역 | 내용 | 다음 행동 |
| --- | --- | --- |
| Header | 이름 또는 텍스트 로고, 소개·기술·프로젝트·경험·연락 앵커, 이력서 | 원하는 섹션으로 이동 |
| Hero | 박지선, 신입 백엔드 개발자, [소개 문구 — 추후 작성] | 프로젝트 보기 / PDF 이력서 |
| About Me | 개발 관심사, 협업 방식, 경험에 근거한 강점 2~3개 | 관련 프로젝트 확인 |
| Tech Stack | 언어·백엔드·데이터·인프라/도구별 기술과 실제 사용 맥락 | 사용 프로젝트로 이동 |
| Projects | 대표 프로젝트 2~3개: 목적, 기간, 팀/개인, 역할, 기술, 핵심 문제 해결 | 독립 상세 페이지 |
| Experience & Education | 기간, 기관, 활동, 기여·학습 결과; 최신순 | 관련 프로젝트 또는 증빙 |
| Contact | 이메일, GitHub, PDF 이력서 | 이메일 작성 / 저장소 / PDF 다운로드 |
| Footer | 이름, 저작권, 필요 시 최종 갱신일 | 페이지 상단 |

About와 Tech Stack은 짧게 구성해 프로젝트까지의 스크롤 부담을 줄인다. Hero의 주요 버튼은 Projects로 직접 연결한다. 기술 숙련도 퍼센트나 근거 없는 별점은 사용하지 않는다.

## 사이트맵과 파일 구조 제안

```text
index.html
projects/
  [project-slug].html        # 실제 프로젝트마다 독립 HTML
assets/
  css/styles.css            # 공통 토큰·레이아웃·반응형
  css/project.css           # 상세 페이지 전용
  js/main.js                # 내비게이션 등 점진적 기능 개선
  images/                   # 프로젝트 이미지·아키텍처
  documents/resume.pdf       # 실제 PDF 수령 후 연결
docs/portfolio-plan.md
```

메인과 상세의 본문은 HTML로 제공해 JavaScript 없이도 읽을 수 있게 한다. GitHub Pages 저장소 하위 경로를 고려해 상대 경로를 사용한다. PDF가 없을 때는 가짜 다운로드 링크 대신 준비 상태를 텍스트로 표시한다.

## 프로젝트 상세 공통 구성

1. 요약: 프로젝트명, 해결하는 문제, 기간, 팀 구성, 주요 기술, GitHub.
2. 담당 역할: 팀 전체 구현과 개인 담당 기능을 구분; 기여도는 근거 없는 백분율 대신 구체적 작업으로 설명.
3. 주요 기능: 사용자 요구사항과 해당 요구를 처리하는 백엔드 구현 연결.
4. 시스템 아키텍처: 실제 구성 요소, 요청·데이터 흐름, 본인 담당 영역, 텍스트 설명. 미사용 기술은 넣지 않는다.
5. 기술 선택: 요구와 제약, 고려한 대안, 선택 이유, 감수한 단점.
6. 기술적 문제 해결: 대표 사례 1~3개를 문제 → 원인/근거 → 대안 → 해결 → 검증 → 남은 한계 순서로 설명.
7. 성과 및 회고: 확인 가능한 결과, 배운 점, 다음 개선 과제.
8. 관련 링크: 저장소, 공개 가능한 API 문서·PR·테스트 등; 프로젝트 목록으로 돌아가기.

다음 항목은 실제 경험이 있는 경우만 활용한다. 모든 항목을 억지로 채우지 않는다.

| 역량 | 상세에 넣을 근거 후보 |
| --- | --- |
| API 설계 | 리소스·상태 코드·입력 검증·오류 응답·인증/인가 결정 |
| 데이터베이스 | ERD, 관계와 제약조건, 트랜잭션 범위, 인덱스, 동시성 처리 |
| 성능 | 병목 관찰, 쿼리 또는 실행 계획, 캐시 정책, 측정 환경과 전후 결과 |
| 안정성 | 실패 처리, 재시도, 중복 방지, 로그, 장애 대응 |
| 테스트 | 단위·통합 테스트 범위, 실패/경계 조건, 재현 방법 |
| 인프라 | 배포 흐름, 실행 환경, CI/CD, 설정·비밀정보 관리 |

수치는 측정 조건·출처가 있을 때만 사용한다. 운영 환경과 로컬 실험을 구분한다. 정량 수치가 없다면 테스트 통과나 오류 재현·해결 등 확인 가능한 정성 결과를 쓴다. 공개 자료에서 비밀키·사용자 정보·기업 비공개 내용을 제거한다.

## 기존 자료와 확인할 내용

README에 아래 내용이 기재되어 있다. 원문 기재 사실과 상세 검증 완료는 구분하며, 포트폴리오 반영 전 사용자 확인을 받는다.

- 표시 이름: 박지선(사용자 확정). 소개 문구는 사용자의 요청에 따라 추후 작성하며, 현재는 placeholder로 둔다.
- 주요 기술 후보: Java, Spring Boot, Spring Security, JPA, MySQL, PostgreSQL, Redis, AWS, Docker 등. 핵심 기술과 보조 기술은 실제 사용 범위 확인 후 선정.
- 프로젝트 구성 확정: 걱정마AI(자동화 서비스), 에브리키친(EveryKitchen), 클리어분양.
- 사용자 확인: 걱정마AI는 초기 개발부터 운영까지 담당했으며, 가장 자신 있게 설명할 수 있는 프로젝트다. 구체적인 담당 기능·기간·성과는 추후 확인한다.
- README의 나머지 운영 및 협업 경험은 기간·역할·공개 가능 범위를 추가 확인한다.

- 제작 순서: 클리어분양 → 에브리키친 → 걱정마AI.
- 사용자가 설명한 내용의 심화 순서: 에브리키친 → 클리어분양 → 걱정마AI.
- 제안한 노출 순서: 걱정마AI → 클리어분양 → 에브리키친. 초기 개발부터 운영까지 설명할 수 있는 걱정마AI를 대표로 배치한다. 노출 순서는 제안 상태이며 디자인 검토 때 함께 확인한다.

## 콘텐츠 수집 양식

프로젝트마다 다음 정보를 받는다. 모르는 항목은 [확인 필요], 제공 전에는 [입력 예정]으로 표시한다.

- 이름 / 한 줄 소개 / 기간 / 개인 또는 팀·인원
- 본인 역할과 직접 구현한 기능 / 기술 스택과 사용 목적
- 가장 어려웠던 문제 / 해결 전 현상 / 원인 / 고려한 대안 / 실제 해결
- 검증 방법과 결과 / 측정 환경·수치 출처(있을 때)
- 저장소 주소 / 공개 가능 자료 / 회고

추가 개인 자료: 공개 이메일, GitHub, 교육·활동 이력, 기존 이력서 PDF 유무. 소개 문구는 추후 별도로 작성한다.

## 디자인·구현 단계에 전달할 제약

- HTML5, CSS3, Vanilla JavaScript. 프레임워크·CSS 라이브러리 없이 정적 구현.
- 라이트 모드: 배경 #F8FAFC, 표면 #FFFFFF, 강조 #2563EB, 제목 #0F172A, 보조 #64748B.
- 한국어 본문 중심, 기술 고유명은 원문 사용. 넉넉한 여백과 읽기 쉬운 본문 폭.
- 시맨틱 구조, 명확한 제목 계층, 키보드 탐색·포커스·본문 건너뛰기, 이미지 대체 설명.
- 화면 크기별 재배치, 모바일 메뉴, 색상 조합의 대비 검증, 동작 감소 설정 반영.
- 절제된 인터랙션; 핵심 본문을 애니메이션이나 JavaScript 실행 여부에 종속시키지 않는다.
- 정적 사이트 범위에서 이메일 링크를 제공한다. 연락 폼이나 외부 서비스는 필요가 확인되면 논의한다.

## 단계별 확인 지점

1. 현재: 정보 구조, 프로젝트 후보, 강조할 경험 확인.
2. 메인 페이지 디자인: 섹션별 와이어프레임과 시각 방향 확인.
3. HTML/CSS/JS 기본 구조 구현.
4. 반응형·인터랙션 구현 및 키보드/화면 크기 점검.
5. 실제 자료 기반 콘텐츠 작성과 사실 확인.
6. 상세 페이지 구현과 콘텐츠·링크 검수.
7. 실제 PDF 연결과 다운로드 확인.
8. GitHub Pages 배포, 공개 URL·경로·모바일·접근성 최종 검수.

사용자 검토 후 다음 단계로 진행한다. 현재 단계에서는 사이트 등록·구현·배포를 수행하지 않는다.
